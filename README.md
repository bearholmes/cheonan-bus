# 천안버스 · Cheonan Bus

천안 지명을 참고한 가상 노선에서 버스를 운전하는 웹 게임입니다. 420초 안에 8개 정류장의 승하차를 완료하고, 정차 정확도와 안전 운전으로 높은 점수를 얻으세요.

JavaScript ES 모듈과 순수 WebGL로 3D 화면을 만들고, Web Audio API로 엔진음을 합성합니다. 런타임 외부 패키지나 별도 서버·API는 필요하지 않습니다. 실제 버스 노선과 지형을 정밀하게 재현한 서비스는 아닙니다.

## 빠른 시작

- Node.js **22.13.0 이상**과 npm이 필요합니다. GitHub Actions는 Node.js 24를 사용합니다.
- WebGL을 지원하는 브라우저가 필요합니다. 오디오는 사용자 입력 후 활성화됩니다.
- 패키지 관리자는 **npm**이며, 재현 가능한 설치를 위해 `package-lock.json`을 함께 관리합니다.

```sh
git clone https://github.com/bearholmes/cheonan-bus.git
cd cheonan-bus
npm ci
npm run dev
```

[개발 서버](http://127.0.0.1:5173/)를 브라우저에서 엽니다. 개발·미리보기 서버는 로컬 주소에만 바인딩되며, 지정한 포트가 사용 중이면 종료됩니다.

## 명령어

| 명령어 | 용도 |
| --- | --- |
| `npm ci` | 잠금 파일 기준으로 의존성 설치 |
| `npm run dev` | 개발 서버 실행 · 포트 5173 |
| `npm test` | Node.js 내장 테스트 실행 |
| `npm run build` | `dist/`에 정적 배포 파일 생성 |
| `npm run preview` | 빌드 결과 미리보기 · 포트 4173 |
| `npm audit` | 개발 의존성을 포함한 알려진 취약점 검사 |

Vite는 개발·빌드 도구로만 사용합니다. TypeScript 타입 검사와 별도 린트 명령은 현재 구성되어 있지 않습니다.

## 조작 방법

| 입력 | 동작 |
| --- | --- |
| `Enter` / `Space` | 시작 화면에서 운행 시작 |
| `W` / `↑` | 가속 |
| `S` / `↓` | 브레이크 |
| `A` / `D`, `←` / `→` | 좌우 조향 |
| `R` | 후진 |
| `Space` | 완전히 정지한 상태에서 도어 열기·닫기 |
| `F` / 전체화면 버튼 | 전체화면 전환 |
| 소리 버튼 | 엔진음 켜기·끄기 |
| 다시 운행하기 버튼 | 결과 화면에서 재시작 |

화면의 터치 버튼으로도 가속·브레이크·조향·도어를 조작할 수 있습니다. 문이 열려 있으면 주행할 수 없습니다. 탭을 떠나면 엔진음은 꺼지지만 운행 제한 시간은 계속 흐릅니다.

## 운행과 점수

- **성공:** 정류장 8개 승하차 완료. **실패:** 시간 소진 또는 미정차 3회 누적.
- **노선:** 천안역 → 삼도상가 → 중앙시장 → 남산중앙시장 → 청과시장 → 방죽안오거리 → 종합터미널 → 도솔광장.
- 첫 정류장은 출발 지점에서 200m, 이후 간격은 400m이며 마지막 정류장은 3,000m 지점입니다. 좌우 회전 구간에서는 안내에 따라 감속하고 직접 조향해야 합니다.
- 승하차는 정류장 중심 기준 좌우 2m·전후 10m의 박스 안, 반경 15m 이내에서 **속도 0 + 도어 열림**일 때 진행됩니다. 하차 1~4명, 탑승 2~8명이 정류장마다 생성됩니다.

| 정차 품질 | 중심과의 거리 | 기본 점수 | 승하차 처리 속도 | 시간 보너스 |
| --- | --- | --- | --- | --- |
| Perfect | 1.5m 이하 | 400점 | 초당 4.5명 | 3초 |
| Good | 5m 이하 | 250점 | 초당 3명 | 없음 |
| Bad | 그 외 인정 구역 | 150점 | 초당 1.8명 | 없음 |

연속 성공마다 점수 배율이 0.2씩 증가하며 최대 3배입니다. 미정차와 연석 충격은 콤보를 초기화합니다. 최고속도는 100km/h지만, 50km/h 초과·급브레이크·급조향·연석 충격은 안전도와 점수를 낮춥니다. 결과 화면에는 점수, 정차 성공률, 안전도, 등급(S/A/B/C)을 표시합니다.

## 프로젝트 구조

```text
index.html                 화면 구성과 진입점
src/
  game.js                  입력, 고정 시간 간격 게임 루프, HUD
  engine.js                운행 상태, 승하차·점수·성공/실패 판정
  route.js                 코스 좌표, 곡선 구간, 운행 상수
  renderer.js              WebGL 셰이더, 도시·버스 렌더링
  audio.js                 엔진음 합성, 음소거·탭 상태 처리
  style.css                화면과 터치 조작부 스타일
public/favicon.svg         정적 리소스
tests/                    규칙·코스·오디오 테스트
.github/workflows/         GitHub Pages 배포
```

## 검증

```sh
npm ci
npm test
npm run build
npm audit
```

`npm test`는 테스트 파일 3개를 실행합니다.

- `rules.test.mjs`: 정차 조건·품질 경계·도어 잠금·점수·실패 등 9개 규칙 검사
- `course.test.mjs`: 속도 제한·정류장 간격·코스 연속성·조향 방향 및 8개 정류장 자동 주행 검사
- `audio.test.mjs`: 모의 오디오 환경에서 초기화·재사용·가속·후진·음소거·탭 전환·운행 종료 검사

이 검사는 게임 로직과 빌드를 검증합니다. 실제 브라우저의 WebGL 출력, 엔진음 청취, 터치·전체화면 동작과 수동 전체 노선 주행은 별도 확인이 필요합니다.

## 빌드와 배포

```sh
npm run build
npm run preview
```

[빌드 미리보기](http://127.0.0.1:4173/)에서 확인한 뒤 `dist/`를 정적 호스팅에 배포합니다. 파일을 직접 여는 대신 HTTP 서버로 실행하세요. 하위 경로 배포는 다음처럼 경로를 지정합니다.

```sh
npm run build -- --base=/cheonan-bus/
npm run preview -- --base=/cheonan-bus/
```

GitHub Pages 워크플로는 `main` 또는 `master`에 푸시하거나 Actions에서 수동 실행하면 `npm ci --include=optional` → 테스트 → 빌드 → 배포를 수행합니다. 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 설정해야 합니다. 일반 프로젝트 저장소는 저장소 이름을 기본 경로로 사용하며, `<소유자>.github.io` 저장소는 `/`를 사용합니다.
